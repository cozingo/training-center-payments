# Мини-учёт оплат учебного центра

- `backend/` — REST API: Express, TypeScript, SQLite (better-sqlite3). Ученики, оплаты, отчёт «должники за месяц».
- `frontend/` — веб-страница для телефона: React, TypeScript, Vite. Список должников и форма добавления оплаты.

## Как запустить с нуля

Нужен Node.js 20.19 или новее (проверено на 24). Другие зависимости не нужны: SQLite встроен через `better-sqlite3`.

```bash
# 1. API — первый терминал
cd backend
npm install
npm run dev            # http://localhost:3000, база создаётся автоматически в backend/data.db

# 2. Фронтенд — второй терминал
cd frontend
npm install
npm run dev            # http://localhost:5173
```

Откройте http://localhost:5173. Чтобы открыть страницу с телефона, подключите его к той же Wi-Fi сети и зайдите по адресу `Network:` из вывода Vite. Фронтенд обращается к API через прокси Vite (`/api` → `localhost:3000`).

Чтобы добавить тестовых учеников (при запущенном API):

```bash
curl -X POST localhost:3000/students -H 'Content-Type: application/json' \
  -d '{"name":"Азиз Каримов","phone":"+998901234567","group":"English A1","monthlyFee":500000}'
curl -X POST localhost:3000/students/1/payments -H 'Content-Type: application/json' \
  -d '{"amount":200000,"date":"2026-10-05"}'
curl 'localhost:3000/debtors?month=2026-10'
```

Тесты и сборка:

```bash
cd backend  && npm test                     # e2e-тесты API (vitest + supertest, SQLite в памяти)
cd backend  && npm run build && npm start   # продакшен-сборка API (PORT, DB_PATH — переменные окружения)
cd frontend && npm run build                # статика в frontend/dist
```

Описание эндпоинтов — в [backend/README.md](backend/README.md), подробнее о фронтенде — в [frontend/README.md](frontend/README.md).

## Что бы я улучшил за ещё одну неделю

1. **Авторизация и роли.** Сейчас любой, у кого есть ссылка, видит телефоны учеников и может добавлять оплаты. Нужны вход для администраторов и роли (администратор или кассир).
2. **Скрипт резервного копирования базы.** Вся история оплат хранится в одном файле SQLite, поэтому нужен скрипт (`npm run backup`), который делает согласованную копию через `VACUUM INTO` или backup API `better-sqlite3` прямо во время работы сервера. Копия получает имя с датой, старые копии удаляются (например, хранить 30 последних). Скрипт запускается по расписанию (cron), а в README описано, как восстановить базу из копии.
3. **Домен и HTTPS.** Купить домен (например, `pay.<название-центра>.uz`) и направить его A-записью на сервер. Поставить перед приложением nginx или Caddy как обратный прокси и выпустить бесплатный SSL-сертификат Let's Encrypt (certbot или встроенный ACME в Caddy) с автоматическим продлением. HTTP перенаправлять на HTTPS: в приложении телефоны учеников и суммы, их нельзя передавать открытым текстом.
4. **Мониторинг и оповещения.** Сейчас о падении сервера узнают только тогда, когда страница перестанет открываться. Что нужно:
   - **Доступность API.** Внешняя проверка `GET /health` раз в минуту (например, Uptime Kuma или UptimeRobot). Сам `/health` стоит расширить, чтобы он проверял ещё и доступ к базе (`SELECT 1`). Оповещение в Telegram, если API не отвечает несколько проверок подряд.
   - **Ресурсы сервера.** Оповещения, когда диск заполнен больше чем на 80% (важно для файла SQLite и резервных копий), а CPU или RAM держатся выше порога дольше нескольких минут. Например, через node_exporter + Prometheus + Alertmanager или более лёгкого агента.
   - **Срок действия домена и SSL.** Предупреждение за 30 и за 7 дней до окончания регистрации домена и SSL-сертификата, чтобы сайт не стал недоступен из-за просроченной оплаты.
